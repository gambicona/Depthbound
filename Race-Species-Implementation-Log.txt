Race / Species Implementation Log
Updated: 2026-05-08

Overview
This update adds race/species selection to hero creation. The flow now asks for a hero name and token picture first, then asks for race/species and subrace, then proceeds to ability score generation and starting gear.

The selected race data is stored directly on the hero and therefore becomes part of normal save files. Existing older saves are normalized to a default Human / Standard Human selection when they do not yet have race data.


Creation Flow
1. Choose save slot.
2. Choose hero name and token picture.
3. Choose race/species and subrace.
4. For Dragonborn, choose draconic ancestry.
5. For Half-Elf, choose the two +1 ability score bonuses.
6. Choose ability score method.
7. Assign ability scores.
8. Choose starting gear.
9. Choose d20 luck mode.
10. Start the dungeon.

Roster hero creation at the Planning Table uses the same race/species flow.


Ability Score Handling
Race/species ability score increases are applied to the final hero stats, not just shown cosmetically.

The stat assignment UI now shows racial bonuses next to each ability. For example, Human shows +1 on STR, DEX, CON, INT, WIS, and CHA. If a player assigns 15 STR to a Human, the select option displays it as 15 +1 = 16.

The stored hero abilityScores already include the racial bonus. This keeps the rest of the existing combat math simple, because attack rolls, saving throws, AC, initiative, HP, and checks already read from abilityScore and abilityMod.

Implemented Engine Hooks

Damage resistances:
- Race-based resistances are stored in fighter.damageResistances.
- Existing damage modifier logic already reads damageResistances, so poison/fire/etc. resistance works with normal attacks, traps, monster specials, and other damage packets that declare a damage type.

Speed:
- Race speed is stored as baseSpeedFeet and speedFeet.
- Existing movement logic uses speedFeet, so 25 ft / 30 ft / 35 ft movement works automatically.

Max HP:
- Hill Dwarf Dwarven Toughness is stored as racialHpPerLevel.
- It applies at creation and during level-up.

Halfling Lucky:
- Implemented inside rollD20ForFighter.
- It rerolls natural 1s before the visible roll is finalized.
- It stacks with the existing d20 luck modes, including Karmic and Tymora's Favorite.

Relentless Endurance:
- Implemented inside applyDamageToFighter.
- It triggers only when a party hero drops from above 0 HP to 0 HP.
- It does not trigger while already down.
- It resets when the hero is rested/prepared at home.

Savage Attacks:
- Implemented inside makeAttack.
- It adds one extra weapon damage die on melee critical hits.
- It does not apply to ranged attacks.

Character inspection:
- The inspect panel now shows species/subrace, resistances, stored proficiencies, and stored future traits when present.


Known Limitations / Future Work

No light system:
- Darkvision has no current gameplay effect and is therefore not implemented.

No spell system:
- Innate spells, cantrips, breath weapons, teleport powers, and similar active supernatural features are stored but not usable.
- The data is structured so later spell/action work can read racialTraits.spellTraits and dragon damage metadata.

No condition-tagged saving throw context:
- Traits like Fey Ancestry and Gnome Cunning need saves to know whether a roll is against charm, sleep, magic, etc.
- Current savingThrow only knows target, ability, and DC, so these traits are stored but inactive.

No tool/social skill gameplay:
- Tool proficiencies, languages, age, alignment, social features, and similar traits are omitted or stored only as notes.

Proficiency enforcement:
- Weapon and armor proficiencies are stored and displayed, but the current equipment/attack system does not yet restrict use based on proficiency.
- This is intentional for now because the existing fighter can already use most gear and the game does not have class/race proficiency enforcement yet.

Legacy rule mix:
- The request asked for 2014-style 5e rules and also included some later playable options.
- The implementation uses 2014-era PHB/Mordenkainen-style ability bonuses where practical, and stores later/spell-heavy features for future systems.
