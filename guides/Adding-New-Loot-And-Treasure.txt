How to add new loot, treasure, and magic items

Current source files to compare against:
- Equipment and potions: src/scripts/content/items/equipment.js
- Treasure, gems, art, valuables: src/scripts/content/items/treasure.js
- Materials/components: src/scripts/content/items/materials.js
- Magic weapons/armor: src/scripts/content/items/magic_items.js
- Magic accessories: src/scripts/content/items/magic_accessories.js
- Basic loot table: src/scripts/content/loot/basic-dungeon.js
- Runtime loot rolls: src/scripts/app/combat-map.js and src/scripts/app/game-state.js

1. Choose the right item file

Normal equipment, ammunition, and healing potions:
src/scripts/content/items/equipment.js

Valuables, gemstones, art objects, and trade goods:
src/scripts/content/items/treasure.js

Crafting/material drops:
src/scripts/content/items/materials.js

Magic weapons and armor:
src/scripts/content/items/magic_items.js

Magic rings, amulets, boots, cloaks, bracers, gauntlets, helms:
src/scripts/content/items/magic_accessories.js

2. Load new item files

If you create a new item file, add it to index.html after registry.js and before app.js. For item files, keep the order near the current item block:

equipment.js
treasure.js
materials.js
magic_items.js
magic_accessories.js

Loot tables, themes, and app.js load later.

3. Treasure items

treasure.js has helper functions:

gemstone("Amethyst", 100, "purple", "Violet quartz associated with nobility and wards.");
artObject("Gold Idol", 2500, "gold", "A palm-sized idol with old temple marks.");
valuable("Silver Trade Bar", 5, "silver", "A stamped trade bar.", { stackable: true });

These helpers register items with:
type: "treasure"
category: "gemstone", "art object", or "valuable"
tags: "treasure", kind tags, and value tags
sell.rate: 1
treasure.valueGp/valueCp
treasure.appraiseDc
treasure.dropWeight

Treasure sells at full value. Lower dropWeight means rarer. If you do not supply dropWeight, treasure.js derives one from value.

4. Magic weapons and armor

Use registerMagicWeapon or registerMagicArmor in magic_items.js:

registerMagicWeapon("magic-dagger-plus-1", "dagger", "Dagger +1", "uncommon", 500, {
  enhancementBonus: 1,
  description: "A balanced dagger with a faint silver edge.",
});

registerMagicWeapon("magic-ember-dagger", "dagger", "Ember Dagger", "uncommon", 850, {
  extraDamage: { count: 1, sides: 4, type: "fire" },
  description: "Deals normal dagger damage plus 1d4 fire damage.",
});

registerMagicArmor("magic-chain-mail-plus-1", "chain-mail", "Chain Mail +1", "rare", 1500, {
  enhancementBonus: 1,
  description: "Old links reinforced with quiet warding marks.",
});

Magic weapons and armor are loot-only by default:
store.buyable: false
store.sellable: true
tags include "magic", "magic-item", "loot:magic"
loot.priceGp controls value cap eligibility
loot.dropWeight controls rarity within the eligible pool
magic holds the actual combat effects

Supported weapon magic includes:
enhancementBonus, attackBonus, damageBonus, extraDamage, resistances, vulnerabilities, properties, curse, unique, dropWeight, tags, description.

Supported armor magic includes:
enhancementBonus/acBonus, resistances, vulnerabilities, properties, curse, unique, dropWeight, tags, description.

5. Magic accessories

Use registerMagicAccessory in magic_accessories.js:

registerMagicAccessory("magic-ring-guardian", "Ring of the Guardian", ["ring1", "ring2"], "uncommon", 1200, {
  effects: { acBonus: 1 },
  description: "Grants +1 AC while equipped.",
});

Slots can be one slot or a list:
"head", "torso", "boots", "cloak", "bracers", "gauntlets", "ring1", "ring2", "amulet", "quiver"

Common passive effects:
abilityScoreBonuses: { str: 2, dex: 1 }
abilityScorePenalties: { dex: -2 }
abilityScoreCaps: { str: 22 }
maxHpBonus
acBonus
acBonusCondition
initiativeBonus
speedBonusFeet
saveBonus
skillBonus
spellAttackBonus
saveDcBonus
resistances
vulnerabilities
attackBonus
attackBonusCondition
damageBonus
damageBonusCondition
extraDamage
extraDamageCondition

Usable accessories can define a top-level use object with charges. Existing code supports charge state on item instances. Common refresh values are "shortRest", "longRest", "newDungeon", or "home".

6. Making loot spawn

The current shared loot logic is in combat-map.js.

Normal monsters:
- 5 percent chance healing potion
- 2 percent chance equipment
- 2 percent chance treasure
- 1-2 percent chance magic, depending on category
- small coin drop

Boss monsters:
- 30 percent chance healing potion
- 18 percent chance equipment
- 75 percent chance treasure
- magic chance is min(55, 20 + category * 8) percent
- better coin drop

Chests and defined loot containers:
- randomChestLoot pulls from healing potions, ammunition, and buyable weapons within party-level budget
- treasure chance = tuning base + partyLevel * tuning perLevel, capped by tuning max
- magic chance = tuning base + partyLevel * tuning perLevel, clamped and capped

Current chest tuning defaults:
treasure: 0.16 + partyLevel * 0.025, max 0.5
magic: -0.005 + partyLevel * 0.015, max 0.14

7. Value caps

Loot eligibility is budgeted by average party level, not only by monster category. Current default caps:

Level 1: treasure 100 gp, equipment 50 gp, magic 0 gp, potion 10 gp
Level 2: treasure 250 gp, equipment 75 gp, magic 500 gp, potion 10 gp
Level 3: treasure 500 gp, equipment 100 gp, magic 900 gp, potion 100 gp
Level 4: treasure 750 gp, equipment 200 gp, magic 1200 gp, potion 100 gp

Level 6: treasure 1000 gp, equipment 750 gp, magic 2500 gp, potion 100 gp
Level 7: treasure 1500 gp, equipment 1500 gp, magic 4200 gp, potion 500 gp
Level 8: treasure 2500 gp, equipment 2500 gp, magic 6000 gp, potion 500 gp
Level 9: treasure 2500 gp, equipment 5000 gp, magic 7500 gp, potion 500 gp
Level 10: treasure 5000 gp, equipment 7500 gp, magic 9000 gp, potion 500 gp

If an item feels too early or too late, adjust loot.priceGp/treasure.valueGp or dropWeight. Do not rely only on rarity text.

8. Loot tables

basic-dungeon.js registers a simple lootTables entry, but the live monster/chest systems also scan registered items directly:

Magic loot candidates:
tags include "loot:magic" or "magic-item"

Treasure candidates:
type is "treasure" or tags include "treasure"

Normal equipment candidates:
buyable equipment from the active dungeon loot table, excluding healing, magic loot, and treasure

The treasureOnly, magicWeaponsAndArmor, and magicAccessories loot tables are useful registry summaries, but combat-map.js still uses the item tags/value fields for random treasure and magic drops.

9. Guaranteed or monster-specific drops

Add extraLoot to a monster template:

extraLoot: [
  { kind: "item", itemId: "gem-amethyst", quantity: 1, chance: 0.25 },
  { kind: "item", itemId: "arrows-20", quantity: 1 },
  { kind: "item", itemId: "bolts-20", quantityDice: { count: 1, sides: 8 } },
  { kind: "randomEquipment" },
]

Supported fields:
kind: "item" or "randomEquipment"
itemId: item id for kind "item"
quantity: fixed amount
quantityDice: rolled amount
chance: 0-1 probability

Ammo quantities update the ammo object. Stackable/component items update quantity.

10. Furniture/container loot

Furniture uses components:

components: [
  C.loot({ count: 2 }),
  C.hiddenLoot({ dc: 13, chance: 0.5, reward: "smallGold" }),
]

C.loot({ count }) rolls randomChestLoot.
C.loot({ items: ["mace", "spear"] }) gives exact items.
C.hiddenLoot can reward smallGold or exact item/items.

11. Testing

- Enable Admin mode.
- Open inventory and use Item Vault search by name, id, or tag.
- Confirm item value, tags, store settings, and magic/treasure fields.
- For random drops, test at the party level where the item should first be eligible.
- For guaranteed drops, kill the monster several times and verify chance/quantity.
- For chest/container drops, inspect or open a furniture object using the relevant component.
