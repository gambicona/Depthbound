NEW MONSTER PACK IMPLEMENTATION INSTRUCTIONS

Purpose:
Use this when adding a new monster pack file. A monster pack should not only register stat blocks. It also needs working tags, load order, theme integration, harvest resources, special ability runtime support, token asset paths, and verification.

Core files to inspect first:
- src/scripts/content/monsters/monster-template.js
- src/scripts/content/monsters/skeletal-undead-pack.js
- src/scripts/content/monsters/zombie-undead-pack.js
- src/scripts/content/monsters/beast-biome-pack.js
- src/scripts/content/monsters/ghost-undead-pack.js
- src/scripts/content/monsters/fiend-devil-pack.js
- src/scripts/content/items/materials.js
- src/scripts/app/combat-map.js
- src/scripts/content/themes/*.js
- index.html

1. Create the pack file

Add a new file:
- src/scripts/content/monsters/<family>-pack.js

Wrap the file:

(() => {
  window.DungeonContent.register("monsters", "monsterId", {
    ...
  });
})();

Use stable camelCase monster ids:
- whisperingShade
- pitImpScout
- graveMistBanshee

Do not rename ids after release unless save migration is handled.

2. Required monster fields

Each monster should include:
- name
- role
- tags
- maxHp
- category
- xp
- ac
- attackBonus
- damage
- damageResistances
- damageVulnerabilities
- damageImmunities
- conditionImmunities
- specialAbility
- initiativeBonus
- speedFeet
- behavior
- token
- tokenArt
- flying

Damage shape:
- count
- sides
- bonus
- type
- attackType
- label
- range

Melee range example:
- range: { kind: "melee", feet: 5 }

Ranged range example:
- range: { kind: "ranged", normal: 60, long: 180, feet: 60 }

3. Categories and bosses

The current pack style uses categories 1-10.

Rough meaning:
- Category 1: party level 1/2
- Category 2: party level 3/4
- Category 3: party level 5/6
- Category 4: party level 7/8
- Category 5: party level 9/10
- Category 6: party level 11/12
- Category 7: party level 13/14
- Category 8: party level 15/16
- Category 9: party level 17/18
- Category 10: party level 19/20

Recommended pack shape:
- 3 normal monsters per category.
- 1 boss monster per category.
- Bosses need the "boss" tag.
- Bosses can include extraLoot randomEquipment.

4. Tags

Tags drive theme spawning, resource drops, and some special handling.

Use broad family tags:
- undead
- ghost
- skeletal
- zombie
- beast
- desert
- fiend
- devil
- construct

Use role/flavor tags:
- boss
- caster
- flying
- brute
- skirmisher
- ranged
- chain
- fire
- poison
- wraith
- banshee

Rules:
- Every monster must have at least one broad family tag.
- Theme spawning uses AND tag groups, so tags must match the theme exactly.
- Do not use theme tags unless the monster should be tied to that theme.
- Use "boss" only for boss-grade monsters.

5. Theme integration

After creating a monster pack, update relevant theme files.

Example:
- monsterTagGroups: [["undead", "ghost"]]
- bossMonsterTagGroups: [["undead", "ghost", "boss"]]

Check:
- The pack is loaded in index.html before any theme that references it.
- The theme has at least one matching normal monster for the current party category.
- The theme has at least one matching boss if bosses can spawn.

6. Index loading

Add the pack in index.html near other monster packs:

<script src="src/scripts/content/monsters/<family>-pack.js" defer></script>

Load order:
- registry before all content
- items before mechanics that reference item ids
- monster packs before themes
- themes before app startup

7. Token assets

Each monster should use:
- tokenArt: "assets/tokens/<monster-kebab-name>.jpg"

If assets are missing, create or update an asset list in implementation notes.

Token field:
- Use one visible letter.
- Avoid duplicate token letters inside a small category when possible, but this is not critical.

8. Resource drops

If the monster family should drop resources, update:
- src/scripts/content/items/materials.js
- src/scripts/app/combat-map.js -> addMonsterMaterialDrops(monster)

Add material components first.

Component items should include:
- stable id
- readable name
- category
- kind
- material
- form
- rarity
- cost
- craftingValueCp for uncommon/rare resources
- tags
- professions
- short
- description

Drop rule example:
- if ids.has("ghost"), add ectoplasm and soul-echo.
- if ids.has("devil"), add devil-blood, hellfire-ember, infernal-iron-shard.

Drop rates:
- Common family parts: about 0.15 to 0.30.
- Uncommon parts: about 0.06 to 0.15.
- Rare parts: about 0.03 to 0.08.
- Boss-only rare parts can be higher, about 0.10 to 0.20.

9. Special abilities: design rule

Every specialAbility entry is just text until combat-map.js recognizes it.

Before adding a special, decide:
- Is it already supported by regex handling?
- Can it be implemented cleanly in the current dungeon combat style?
- Should it be simplified?
- Should it be cut?

Cut or simplify abilities that require:
- Full possession of player characters.
- Summoning/retinue systems not already present.
- Rewriting terrain or walls during combat.
- Disabling random action buttons.
- Complex law/pact rules with many player exceptions.
- Persistent battlefield phase changes without a terrain/hazard system.

Good ability shapes for current combat:
- On-hit extra damage after a saving throw.
- On-hit poison, slow, fear, shaken, restrained, snared, pushed, or pulled.
- Once-per-fight area burst damage.
- Once-per-fight area debuff.
- Simple start-of-turn aura.
- Simple defensive reduction.
- Simple reactive melee damage.
- One-time death defiance for bosses.

11. Special ability implementation guidelines

On-hit specials:
- Put them in applyMonsterOnHitSpecials.
- Respect shouldUseMonsterSpecial("onHit").
- Use rollSavingThrow.
- Use applySpecialDamage.
- Apply short status effects with expiresAtEndOfTurn or durationRounds: 1.

Active specials:
- Put them in maybeUseMonsterStartSpecial.
- Use tryMonsterAreaSpecial for damage.
- Use tryMonsterStatusSpecial for debuffs.
- Active specials consume monster.hasAction.
- Limit targets with maxTargets when needed.

Defensive/reactive specials:
- Use maybeUseMonsterDamageReduction for parries/mirror effects.
- Use applyMonsterReactiveSpecials for melee thorns, barbs, and ripostes.
- Use maybeUseMonsterDeathDefiance for "survives at 1 HP once" effects.

Movement:
- Use pushTargetAway for pushes.
- Use pullTargetToward for pulls.
- Do not directly move fighters without walkability/occupancy checks.

12. Balance notes

Damage:
- Basic attack damage should be the main monster threat.
- Special damage should add spice, not double every attack.
- Area specials should usually hit at most 3 targets unless it is a high-category boss.

Status effects:
- Use short durations.
- Avoid hard action locks except for rare high-tier abilities.
- Prefer frightened/shaken/hamstrung/restrained over full stun.
- Bosses should not be permanently disabled by one failed save.

Resistances:
- Ghosts often resist mundane physical damage and are vulnerable to radiant.
- Devils often resist cold/necrotic, are immune to fire/poison, and are vulnerable to radiant or cold depending on subtype.
- Do not over-stack resistances at low category.

13. Loot and XP

XP should scale with category and boss status.

Boss extra loot example:

extraLoot: [
  { kind: "randomEquipment" },
]

Avoid adding too much fixed equipment to every monster. Use material drops for repeatable reward texture.

14. Verification checklist

Syntax:
- node --check src/scripts/content/monsters/<family>-pack.js
- node --check src/scripts/app/combat-map.js if edited
- node --check src/scripts/content/items/materials.js if edited
- node --check src/scripts/content/themes/<theme>.js if edited

Registration smoke test:
- Stub window.DungeonContent in Node.
- require materials if new drops were added.
- require the monster pack.
- require themes that reference it.
- Count normal and boss monsters by tag.
- Confirm new material ids exist.

Example expectations:
- Monster count > 0.
- Boss count > 0.
- Every monster has tags, damage, behavior, tokenArt.
- Every specialAbility entry is either supported, deliberately simplified, or deliberately cut.

Browser/playtest:
- Generate a dungeon theme that uses the pack.
- Confirm matching monsters spawn.
- Start combat and check console/log for errors.
- Kill a few monsters and confirm resource drops can appear.
- Test at least one low-category and one higher-category fight if possible.

15. Common mistakes

- Adding a pack file but forgetting index.html.
- Adding monsters with tags that no theme selects.
- Adding bosses without the "boss" tag.
- Writing specialAbility text but no combat-map support.
- Adding resource drops for item ids that do not exist.
- Using too many hard disables.
- Giving low-tier monsters too many resistances.
- Forgetting tokenArt asset paths.
- Letting a theme reference a monster family before its pack is loaded.
